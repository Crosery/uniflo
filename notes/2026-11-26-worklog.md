# 2026-11-26 · Worklog

## 网关高并发低延迟优化（全链路锁、快照、用量/全文/适配器并发改造）

分支 `stage`。工作区原有 `.gitignore`、`crates/uniflo-search/src/fts.rs`（`contentions` / `is_locked`）、`crates/uniflo-search/tests/fts.rs` 的未提交改动保持原样。

### 根因（基于本机实测 6,185–6,190 会话 / 5,345 源 / 51 MB `usage-v1.json` / 3.0 GB `fts-v2.sqlite`）

1. **`Engine::sessions()` 每次请求在 Tokio 工作线程上全量深拷贝并排序**：克隆全部 ~6,190 条 `Session` 再排序，且后台 `apply_live()` / `tick()` 每秒 ~11 次无条件拿 `state.write()`，在 macOS 写优先 `pthread_rwlock` 下形成读队列堆积。
2. **后台 I/O 持锁阻塞读请求**：`rescan()` 与 `hot_sources()` 在 `state.read()` 内执行全量/热源磁盘 `stat`；`save_usage_cache()` 在 `usage.read()` 内序列化并落盘 51 MB JSON（耗时 ~1.8 s），且原 `/v1/health` 经 `stats()` → `usage_progress()` 间接竞争 `usage.read()`。
3. **用量聚合热点与时区锁争用**：`Tz::Local` 逐步骤调用 libc `localtime_r`（macOS 全局互斥锁），导致 10 并发 `/v1/usage?group_by=day&since=30d` 串行耗时 1,278 ms；首次优化时每步调 `std::env::var_os("TZ")` 同样触发 Rust 全局 `ENV_LOCK` 跨核争用；会话级维度未利用整账本聚合结果，每次仍遍历 ~38 万步。
4. **全文检索并发热点**：`Fts::status()` 在 Tokio 线程跑 SQLite 查询；`Fts::search()` 每次执行 `SELECT count(*) FROM docs` 全表扫描、5 次独立 `meta` 查询、逐条命中拿 `shared.lock()` 并克隆 `Session`，并发冷查询无全局验证线程上限。
5. **适配器与历史分页开销**：`Antigravity::sidecars()` 将全局共享的 `conversation_summaries.db` / `-wal` 与 `last_conversations.json` 挂到全部 ~700 个 Antigravity 会话上，任意单会话写入都会触发全量重读、写锁与缓存失效（空载 CPU 45%）；`WithSidecars::changed` 每次反序列化并克隆完整 `serde_json::Value`；`JsonlAdapter::history()` 存在二次 JSON 解析；`antigravity` 跨 SQLite 读取持 `Mutex`。
6. **网关缺少同键合并、版本缓存与 CPU 限流**：相同并发读重复计算，重 CPU 未命中突发（模糊检索/用量/全文）直接淹没全部核心并拉高 `/v1/health` 尾延迟。

### 改动

- **引擎无克隆快照与无锁保存**
  - `crates/uniflo-core/src/engine.rs`、`crates/uniflo-core/src/engine_archive.rs`、`crates/uniflo-core/src/lib.rs`：`Entry.session` 改为 `Arc<Session>`，引入按 `state_gen` 懒发布、按最近活动预排好的不可变 `SessionSnapshot`（含 `by_key`、`working`、`by_adapter`）与无锁 `HealthSnapshot`；`apply_live()` / `tick()` 先做只读快检、无变化不拿写锁；`hot_sources()` / `rescan()` 先短锁拷贝游标再 `spawn_blocking` 做磁盘检查；`save_cache()` 短锁克隆 `Arc` 指针后无锁序列化；新增 `history_page()` 避免归档二次解码。
- **用量引擎与时区并发**
  - `crates/uniflo-core/src/usage/tz.rs`：缓存 `/etc/localtime` 解析结果并新增 `Tz::resolve() -> ResolvedTz`，每次查询仅检查一次 `TZ` 环境变量；非 DST 时区（如 `Asia/Shanghai`、`UTC`）对现代时间戳走单次比较常量偏移快路径。
  - `crates/uniflo-core/src/usage/mod.rs`、`store.rs`、`report.rs`、`engine_usage.rs`、`pricing/mod.rs`：`UsageIndex::sources` 改 `Arc<SourceLedger>`，`save_usage_cache()` 走 `source_snapshot()` 无锁落盘；`usage_progress()` 改原子计数；`Ledger` 维护 `ts_range` 与预聚合 `LedgerTotals`，会话级维度命中 `contained_in()` 时 O(1) 累加；时间维度按整数分桶并仅在收尾格式化字符串；`Pricing::refresh()` 增加原子时间窗快路径，`Loaded::memo` 与 `project_of` 的 `MEMO` 改 `RwLock`。
- **适配器与搜索并发**
  - `crates/uniflo-core/src/jsonl.rs`：`JsonlAdapter::history()` 合并为单次 JSON 解析。
  - `crates/uniflo-adapters/src/common.rs`、`crates/uniflo-adapters/src/antigravity.rs`：`WithSidecars::changed` 按引用比对 `sig` 消除状态树克隆；`Sidecar` 新增 `sidecar_sig()`，`Antigravity` 对共享摘要库按单会话确定性 FNV-1a 哈希生成签名（避免单会话更新触发 ~700 会话重读）；`summaries` 与 `conv_dbs` 改 `RwLock` 并在加载 SQLite 前释锁。
  - `crates/uniflo-search/src/lib.rs`：新增零克隆 `search_refs()`、复用 `thread_local!` `Matcher` 与缓冲、无分配 ASCII `cwd_contains()`。
  - `crates/uniflo-search/src/fts.rs`、`fts/cache.rs`、`fts/store.rs`：单查询取 `meta` 计数、缓存热/冷计数供 `Fts::status()` 无锁读取、消除 `SELECT count(*) FROM docs` 全表扫描、排序路径零克隆并仅物化 `limit` 条命中、`BlockCache` 改 `RwLock` + 原子 LRU 时钟、`ColdCache` 存 `Arc`、冷层并行验证加全局线程槽上限与只读连接池上限。
- **网关版本缓存、Singleflight 与 CPU 限流**
  - `crates/uniflo-gateway/src/cache.rs`（新增）、`lib.rs`、`usage.rs`、`search.rs`、`cleanup.rs`：新增按精确代数（`state_gen` / `usage_gen` / `pricing_gen` / `fts_gen`）隔离的有界 `ResponseCache`（相对时间参数跳过缓存）、取消安全异步 `Singleflight`、受 `cpu_permits` 信号量保护的 `spawn_blocking` 重计算下沉；`/v1/health` 改走 `health_snapshot()`。
  - `crates/uniflo-gateway/tests/concurrency.rs`（新增）：5 个多场景高并发集成测试（96 并发混合读一致性、读写并发 + SSE 实时流 + 精确缓存失效、24 并发不同 FTS 查询 + 实时写入、锁无关缓存保存并发读、Singleflight 合并与相对时间准确性）。
  - `docs/architecture.md`：同步更新「并发与一致性」章节。
