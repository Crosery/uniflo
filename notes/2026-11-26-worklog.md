# 2026-11-26 · Worklog

## 网关高并发低延迟优化（全链路锁、快照、用量/全文/适配器并发改造）

分支 `stage`。工作区原有 `.gitignore`、`crates/uniflo-search/src/fts.rs`（`contentions` / `is_locked`）、`crates/uniflo-search/tests/fts.rs` 的未提交改动保持原样。

### 根因（基于本机实测 6,185–6,190 会话 / 5,345 源 / 51 MB `usage-v1.json` / 3.0 GB `fts-v2.sqlite`）

1. **`Engine::sessions()` 每次请求在 Tokio 工作线程上全量深拷贝并排序**：克隆全部 ~6,190 条 `Session` 再排序，且后台 `apply_live()` / `tick()` 每秒 ~11 次无条件拿 `state.write()`，在 macOS 写优先 `pthread_rwlock` 下形成读队列堆积。
2. **后台 I/O 持锁阻塞读请求**：`rescan()` 与 `hot_sources()` 在 `state.read()` 内执行全量/热源磁盘 `stat`；`save_usage_cache()` 在 `usage.read()` 内序列化并落盘 51 MB JSON（耗时 ~1.8 s），且原 `/v1/health` 经 `stats()` → `usage_progress()` 间接竞争 `usage.read()`。
3. **用量聚合热点与时区锁争用**：`Tz::Local` 逐步骤调用 libc `localtime_r`（macOS 全局互斥锁），导致 10 并发 `/v1/usage?group_by=day&since=30d` 串行耗时 1,278 ms；首次优化时每步调 `std::env::var_os("TZ")` 同样触发 Rust 全局 `ENV_LOCK` 跨核争用；会话级维度未利用整账本聚合结果，每次仍遍历 ~38 万步。
4. **全文检索并发热点**：`Fts::status()` 在 Tokio 线程跑 SQLite 查询；`Fts::search()` 每次执行 `SELECT count(*) FROM docs` 全表扫描、5 次独立 `meta` 查询、逐条命中拿 `shared.lock()` 并克隆 `Session`，并发冷查询无全局验证线程上限。
5. **适配器与历史分页开销**：`Antigravity::sidecars()` 将全局共享的 `conversation_summaries.db` / `-wal` 与 `last_conversations.json` 挂到全部 ~700 个 Antigravity 会话上，任意单会话写入都会触发全量重读、写锁与缓存失效（空载 CPU 45%）；`WithSidecars::changed` 每次反序列化并克隆完整 `serde_json::Value`；`JsonlAdapter::history()` 存在二次 JSON 解析；`antigravity` 跨 SQLite 读取持 `Mutex`。
6. **网关缺少同键合并、版本缓存与 CPU 限流**：相同并发读重复计算，重 CPU 未命中突发（模糊检索/用量/全文）直接淹没全部核心并拉高 `/v1/health` 尾延迟。

## `uniflo update` 工作目录修复与网络测速优先的智能选源

### 背景与根因

- 用户在家里 Mac 的 `~/nas2` 目录下运行 `uniflo update`（以及 `UNIFLO_MIRROR=official uniflo update`）时，均报错 `error: Unable to proceed. Could not locate working directory.: No such file or directory (os error 2)`。根因是 `crates/uniflo-cli/src/update.rs` 启动 `cargo install` 时直接继承了调用方可能已失效/卸载的当前目录（且可能误读当地 Rust 项目的 `.cargo/config.toml`）。
- 原先镜像选择仅按系统时区决定，开启代理或处于海外但使用中国时区的机器会被强行切到国内镜像，刚发版时还可能遇到镜像同步滞后；同时 `binary` 升级与安装脚本顺序先等 GitHub 超时（8 s）才切加速站。

### 改动

- **工作目录隔离与自动回退**（`crates/uniflo-cli/src/update.rs`、`crates/uniflo-cli/tests/dist.rs`）：
  - `run_cargo_once()` 与失效 cwd 下的 `setup --after-update` 显式切到系统临时目录（`safe_workdir()`），`uniflo-core::install` 中 `curl` / `tar` / `powershell` / `--version` 子进程也显式使用临时工作目录。
  - `cargo install` 遇网络/索引下载类错误时自动切换到下一个候选源重试；新增真实子进程端到端测试 `cargo_update_works_from_deleted_cwd_and_retries_on_mirror_error`（在 `rmdir` 后的失效目录中执行 `uniflo update` 并模拟首源下载失败自动切次源）。
- **网络测速优先 → 时区兜底 → `UNIFLO_MIRROR` 覆盖**（`crates/uniflo-core/src/{mirror.rs,update.rs,install.rs}`、`scripts/install.sh`、`scripts/install.ps1`、`docs/decisions/ADR-0009-预编译分发与自升级.md`、`README.md`）：
