# 2026-10-06 worklog

> 排查并修复 MiniMax Code 适配的「实时性」与「适配」两类缺陷：助手行原地重写导致流式内容不可见、`tool_calls` 整块丢弃、回合完成窗口被时间戳毒化丢 `turn_end`、模型识别滞后、`live()` 缺失导致状态只能靠超时收敛。随后在实机 LuoXi（Windows 11 x64）上排查 Windows 适配，修复 opencode 系路径、argv 进程匹配与 PEB 工作目录三处失效。

状态：`current` · 更新：2026-10-06

## MiniMax 根因（对照真实库 `~/.minimax/v2/sqlite/runtime-state.sqlite` 逐条验证）

1. **原地重写不可见**：`local_runtime_message_rows` 的助手行在回合进行中会被 UPDATE（`tool_calls` 结果回填、文本定稿），`id` 不变。follow 只按 `id>prev.row_id` 增量取行 → 流式期间零事件，直到 checkpoint 后 summary 重扫才一次性出现。
2. **工具调用全部丢失**：`expand` 只处理 `msg_content`/`thinking_content`/`usage`，从不读 `tool_calls` 数组（真实数据 187 条含工具行；`tool_call_status` 以数字或字符串两种形态出现，2=成功、3=失败、1=进行中）。
3. **`turn_end` 可被永久吞掉**：完成检测用 `completed_at_ms` 的 `MAX` 窗口分页；任何一条时钟偏移/粗粒度的完成时间戳都会毒化水位线，后续所有 `turn_end` 落入窗外不再发出，会话卡死 `work`。烟测中真实复现（tr2 的 turn_end 丢失，只能靠进程退出兜底转 idle）。
4. **模型识别**：只从 `role IS NULL` 的诊断行挖 `model_phase_started`；每回合助手行的 `context_usage_telemetry.model` 才是权威且更新的来源（真实库 202 条）。
5. **`live()` 缺失**：文档表格进程映射为「—」，work/idle 全靠事件 + 10 分钟 stale 收敛；`turn_ingress` 的 `accepted` 行 + `ProcCache`（`ps`+`lsof`，argv 含 `MiniMax Code.app/Contents/`）可直接给出可信 Work 信号。

## MiniMax 修复

- `State.open: Vec<OpenRow{id, hash}>`：跟踪未闭合回合的助手行（FNV-1a 载荷哈希，上限 256），每次 follow 按主键回读，哈希变化即重发同 id 事件（`partial=true`）；回合闭合时做一次非 partial 终扫，槽位序保证终扫先于 `turn_end`。
- 回合分页改为 rowid（`accepted` 时插入，单调）+ `prev.turns` 显式开放回合 id 集合，闭合按 id 查，彻底移除 `acc_ms/comp_ms` 时间窗口。
- `expand` 新增 `tool_calls → ToolCall/ToolResult`（args/result 字符串解码、`content[] → text_of`、status 3 → `is_error`）、telemetry 模型（与 diag 行按 ts 取最新）。
- `live()`：进程在 + `accepted` 回合（24h 内）→ `Status::Work`；进程消失 → `exited` 兜底 idle。`live_roots()` 指向 sqlite 目录，wal 写入即触发探针。
- 摘要/跟随/历史三条路径统一走 open-turn 判定；`history` 也输出 partial。

## Windows 适配排查（实机 LuoXi：Win11 22631 x64，rustc 1.91，经 wanctl 驱动）

1. **opencode 系路径回归**：CLI 在 Windows 仍用 XDG 布局 `~\.local\share\opencode\opencode.db`（实测存在），而 `data_home()` 只返回 `%LOCALAPPDATA%` → 真实数据 0 会话。改为双候选、优先实际存在数据库的路径（`data_db`）。修复后 scan 出 `opencode sess=2`。
2. **`is_proc` 不认 Windows argv**：`Win32_Process.CommandLine` 带引号反斜杠路径（`"C:\…\opencode.exe"`），旧逻辑 `rsplit('/')` + 精确名永远不匹配 → opencode/kilo/zcode/mimocode 的 `live()` 在 Windows 全部失效。改为去引号、`['/','\\']` 取基名、去 `.exe`、小写比较；新增 `is_proc_matches_posix_and_windows_argv` 回归测试。
3. **PEB 工作目录读取**：Windows `procs::list` 恒 `cwd: None`，opencode `live()`（`session.directory = cwd` 精确匹配）与 pi/omp 第 3 级映射在 Windows 是死代码。新增 `process_cwd()`：`NtQueryInformationProcess` + `ReadProcessMemory` 读 PEB（x64 偏移 `+0x20`/`+0x38`，windows-sys 0.59 的 `RTL_USER_PROCESS_PARAMETERS` 是隐藏字段的 stub），去 `\\?\` 前缀与尾分隔符；非 x64 返回 `None`。windows-sys 增加 `Win32_System_Kernel`、`Win32_System_Diagnostics_Debug`、`Wdk_System_Threading` 三个 feature。
4. **minimax 进程匹配 Windows 化**：`is_minimax` 的 `MiniMax Code.app/Contents/` 只存在于 macOS；Windows 分支改为大小写不敏感匹配 `minimax code`。minimax 未安装于 LuoXi（`~\.minimax` 不存在），`live()` 的打开文件精确映射在 Windows 退化为 argv 启发（docs 已注明）。
5. **无问题项**：watch.rs（notify 自动选 ReadDirectoryChangesW）、cache.rs（`dirs::cache_dir`）、cline/roo（`%APPDATA%` 实测 18 会话）、`file_mtime_ms`/`now_ms` 与 APFS 无关。

## WorkBuddy 用户输入解析（下午追加）

WorkBuddy 把真人输入包在 `<user_query>…</user_query>` 里，与 ~7KB 的 `<system-reminder data-role="user-context">`（OS / 身份 / skills 提示）拼进同一个 `input_text` part；旧 `user()` 整坨当用户消息 → preview / `--json` 正文全是 reminder，真人文本被埋。

根因数据（本机真实库，只统计不打印正文）：67 个 user part 里 56 个带 `<user_query>`；Windows（LuoXi）与 macOS 的 blob 形状完全一致 → 单一跨平台修复，无需 cfg 分支。Linux 未实机验证（代码平台无关）。

修复（`crates/uniflo-adapters/src/workbuddy.rs`）：`split_user_query()` 取标签内文本为真人消息（`synthetic=false`，id 不变），标签外的注入上下文归并为 `synthetic=true` 消息（id 后缀 `:ctx`，先发），无标签的纯文本照常走真人分支；`INJECTED_PREFIXES`（`<task-notification>`、`<system-reminder`、`<image_local_path>`、`Caveat:`、`Please continue with the`）与 `providerData.isMeta` 标 synthetic；`image_blob_ref` 渲染 `[图片 <mime>]`。

## v0.1.3 自动更新（`feat`）

决策 `ADR-0005`：检查用系统 `curl`（macOS + Win10 1803+ 自带）GET crates.io 稀疏索引，安装用 `cargo install uniflo --force` —— 与 `core::procs` 调 `ps`/`lsof` 同一先例，**零新增生产依赖**（Cargo.lock 里原本没有任何 HTTP/TLS/semver crate）。

- `crates/uniflo-core/src/update.rs`：`INDEX_URL`、`is_newer`（三位号 + 预发布 rank，release 高于同预发布号）、`parse_latest`（NDJSON 逐行、跳过 yanked、跳过非 `X.Y.Z[-pre]`）、`fetch_latest`（`curl -fsS --max-time 15`，UA `uniflo/<ver>`；Windows 用 `curl.exe`）、`check()`（永不失败，错误进 `UpdateInfo::error`）。
- 守护进程：`EngineOptions::update_check: Option<Duration>`（默认 `None`）；`daemon` 默认开启、启动后一次 + 每小时，`--no-update-check` 关闭。走既有 `Msg`/`spawn_blocking` 单写者模式（`UpdateTick` / `UpdateApplied`，`updating` 防重入），结果写 `Stats::update`，发现新版 `tracing::info` 一条。
- 网关：`/v1/stats` 自动带 `update`；`/v1/health` 加可选字段 `update_available`、`latest_version`（网关 API，非 wire schema，`docs/api.md` 已同步）。
- CLI：`uniflo update [--check] [--json]`；`--json` 有新版退出码 10；非 check 时执行 `cargo install uniflo --force`，macOS 探测 `launchctl list` 命中 `com.crosery.uniflo` 则 `kickstart -k` 重启（KeepAlive 自恢复），否则打印重启指引；Windows 提示运行中的 exe 需先停 daemon。
- 版本 `0.1.2 → 0.1.3`（workspace + 5 个 path 依赖），`README.md` 加「升级」节。
