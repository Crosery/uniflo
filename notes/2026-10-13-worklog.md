# 2026-10-13 · Worklog

## 1. Windows 平台定期终端黑框弹窗彻底根除

### 现象与根因
- 用户在 Windows 上运行 Uniflo 守护进程时，桌面上每隔几秒钟就会闪现或弹出一个黑色终端/控制台窗口，严重打断输入和日常操作。
- **根因分析**：
  1. 守护进程在 `uniflo-core::procs::raw_procs()` 中每 2 秒运行一次 `powershell Get-CimInstance Win32_Process ...` 获取进程命令行。在 Windows 下，`std::process::Command::new("powershell")` 启动控制台子系统进程，默认如果没有指定 `CREATE_NO_WINDOW`（`0x08000000`），Windows 就会给子进程分配一个独立的 Console 窗口并闪现在屏幕中央。
  2. 价格同步（`pricing::sync::fetch`）、更新检查（`update::fetch_releases`）、二进制解压自更新（`install::unpack` / `install::fetch`）以及 setup 脚本中调用 `curl.exe`、`powershell.exe`、`tar.exe`、`cmd.exe` 时均未设置 `CREATE_NO_WINDOW`。
  3. 每 2 秒启动一次 PowerShell 的开销极高（冷启动 300ms+，单核高 CPU 占用）。

### 改动
- `crates/uniflo-core/src/util.rs`：
  - 新增 `pub fn silent_cmd(program) -> std::process::Command`，在 Windows 下统一注入 `creation_flags(0x08000000)`（`CREATE_NO_WINDOW`），确保任何后台进程执行绝不产生窗口。
- `crates/uniflo-core/src/procs.rs`：
  - 新增 `has_candidate_processes()`：利用 Win32 `CreateToolhelp32Snapshot`（`Process32FirstW` / `Process32NextW`）进行 0.1 毫秒级进程快照极速预检。如果系统中根本没有运行相关的候选进程（`bun`, `node`, `omp`, `agy`, `antigravity`, `dsh`, `opencode`, `prime`, `minimax`, `droid`, `qwen`, `pi` 等），直接返回空，完全不拉起外部 PowerShell 进程。
  - 当存在候选进程时，通过 `silent_cmd("powershell")` 执行 CIM 查询，保证后台无弹窗；
  - 将 `raw_procs()` 缓存 TTL 适度从 2 秒调整为 5 秒，进一步降低系统负载。
- `crates/uniflo-core/src/pricing/sync.rs`、`crates/uniflo-core/src/update.rs`、`crates/uniflo-core/src/install.rs`、`crates/uniflo-cli/src/setup/mod.rs`：
  - 全量将外部命令调用切换为 `silent_cmd`，彻底消除所有定期和后台静默命令的控制台闪窗。

## 2. Web 控制台恢复命令可见性提升与 Windows 终端适配

### 现象与根因
- 用户在 demo 页面中看不到会话恢复命令及相关信息：
  1. 会话详情头部（`#sh-meta`）中未显式展示恢复命令，用户若未注意到右上角的“恢复”菜单按钮，在整个页面完全找不到恢复命令；
  2. 原后端在会话未记录 `cwd` 且 `needs_cwd == true` 时，直接将 `info.supported` 判定为 `false` 并将 `command` / `command_powershell` 全部置为 `None`，导致前端按钮禁用且命令留空；
  3. 前端从未展示过 `command_powershell`，在 Windows 下也只展示 POSIX/Bash 格式命令（`cd 'C:\...' && claude ...`），在 Windows 终端中运行容易语法报错；
  4. 原网关的 `POST /v1/sessions/{key}/open-terminal` 对 Windows 直接返回 501 Not Implemented，前端也写死 `!IS_MAC` 不展示终端选项；
  5. 缺少对 `workbuddy`, `qwen`, `minimax`, `prime`, `factory` 等 harness 的恢复命令映射支持。

### 改动
- `crates/uniflo-core/src/resume.rs`：
  - 扩展支持 `workbuddy`, `qwen`, `minimax`, `prime`, `factory` 的 CLI 恢复命令映射；
  - 当会话缺少 `cwd` 时，生成基础恢复命令行并在 `reason` 提示“建议在原工作目录中执行”，不再清空命令或直接阻断；
  - `Terminal` 枚举扩展支持 `Wt`（Windows Terminal）、`Powershell`（Windows PowerShell）、`Cmd`（命令提示符），并新增 `windows_terminal_argv()` 构造 Windows 终端启动参数。
- `crates/uniflo-gateway/src/agent.rs`：
  - `open_terminal` 在 Windows 下正式支持拉起终端窗口（`wt.exe` / `powershell.exe` / `cmd.exe`），通过 `spawn()` 非阻塞唤起；
  - `installed(t)` 在 Windows 下自动检测 `wt.exe`、`powershell.exe`、`cmd.exe`。
- `examples/web/index.html` & `crates/uniflo-gateway/src/index.html`：
  - 在会话详情头部（`#sh-meta`）新增精致的 `.resume-cmd` 代码胶囊芯片（如 `▶ claude --resume f383e73f`），支持鼠标悬停预览完整命令、点击一键复制，让恢复命令始终醒目可见；
  - 增加 `IS_WIN` 环境自适应：Windows 环境下优先展示 PowerShell 命令，并支持分别复制 PowerShell 和 CMD/Bash 命令；
  - 恢复菜单在 Windows 下提供“在 Windows Terminal 中打开”、“在 PowerShell 中打开”、“在 CMD 中打开”一键启动支持。
