## 1. Antigravity 状态判断与解析修复

### 现象与根因

- `antigravity:a81a1679` 会话中：
  1. `GENERIC` 步骤（Antigravity / `agy` CLI 的通用工具执行结果，本机 151 个会话中 963/963 全部对应 `PLANNER_RESPONSE` 排队的工具调用）被原适配器按 `Body::AssistantMessage` 发出：
     - 导致 `list_dir`、`view_file` 等 `ToolCall` 没有关联结果（界面显示 `—`），工具输出被渲染为独立助手消息；
     - 更关键的是，工具结果之后 `StatusTracker.reason` 变成 `"assistant_message"`，触发 90 秒 `settle_ms` 快速超时窗口（而非 `tool_result` 的 600 秒 `stale_ms` 窗口），在模型长耗时思考生成下一轮 `PLANNER_RESPONSE` 期间（`step 5` 耗时约 5 分钟）过早判定为 `idle · stale`。
  2. `link()` 从 `pending` 队列弹出工具调用时丢弃了工具名称 `name`，且工具输出头部的 `Created At:` / `Completed At:` 未解析剥离。
  3. `USER_INPUT` 步骤未剥离 `<USER_REQUEST>...</USER_REQUEST>` 与 `<ADDITIONAL_METADATA>...</ADDITIONAL_METADATA>` / `<USER_SETTINGS_CHANGE>...</USER_SETTINGS_CHANGE>` 包装标签，导致消息正文与会话预览带原始 XML 标签。
  4. 缺少旁路元数据（`annotations/<id>.pbtxt`、`conversations/<id>.db`、`conversation_summaries.db`、`cache/last_conversations.json`）读取与 `live()` 进程存活探测（`agy` / `antigravity`）。

### 改动

- `crates/uniflo-adapters/src/antigravity.rs`：
  - 移除将 `GENERIC` 当作 `AssistantMessage` 的分支，统一走工具结果分支；`link()` 保留工具调用名 `name`，并由 `parse_tool_output()` 提取 `Completed At:` 作为结果时间戳、剥离头部 `Created At:` / `Completed At:` 元数据行。
  - 新增 `clean_user_input()`，剥离 `USER_INPUT` 中的 `<ADDITIONAL_METADATA>`、`<USER_SETTINGS_CHANGE>` 尾部块与 `<USER_REQUEST>...</USER_REQUEST>` 外层标签。
  - 实现 `Sidecar`（`WithSidecars<Antigravity>`）：只读读取 `annotations/<id>.pbtxt`、`conversations/<id>.db`（`trajectory_metadata_blob` 中的 `file://` 工作区 URI）、`conversation_summaries.db` 与 `cache/last_conversations.json` 补全会话 `title`、`cwd`、`parent`；无旁路 `cwd` 时回退取工具调用参数中的工作目录。
  - 实现 `live()` 进程探测：通过 `ProcCache` 识别运行中的 `agy` / `antigravity` 进程（排除 `--bg-updater` 与管理子命令），按 `--conversation` 参数 → 打开的 `transcript.jsonl` / `conversations/<id>.db` 文件句柄 → `cwd` 映射到活跃会话。

## 2. Claude Code 与常驻进程会话状态判断修复

### 现象与根因

- 3 个数小时至 1 天前已结束的 Claude Code 会话（`claude:040ec04d`、`claude:fc9fc538`、`claude:9509b777`）因终端 REPL 进程仍存活，持续被判定为 `work`：
  1. `040ec04d` 会话以 `"type": "continued-in"` 结转到新会话（且 `~/.claude/sessions/46884.json` 含 `"parkedJobId"`），但 `"continued-in"` 原本在 `IGNORED` 中未产出 `TurnEnd`；
  2. `fc9fc538`（`6918.json` `"status": "shell"`）与 `9509b777`（`1250.json` `"status": "idle"`）在用户发送消息后中断/切入 shell，未写回复记录，但 `~/.claude/sessions/<pid>.json` 已明确记录为 `"shell"` / `"idle"`；原 `claude.rs` 的 `live()` 忽略了该状态字段（固定返回 `status: None`）；
  3. 原 `uniflo-core::status::effective()` 在 `live_pid == true` 且 `live_status == None` 时完全禁用了超时（`!live_pid`），导致任何未写出 `TurnEnd` 但终端 REPL 未关的会话永久停留 `work`。

### 改动

- `crates/uniflo-adapters/src/claude.rs`：
  - `"continued-in"` 记录产出 `Body::TurnEnd { reason: Some("continued_in") }`；`system` 的 `"away_summary"` / `"agents_killed"` 追加 `TurnEnd`；
  - `live()` 在 `~/.claude/sessions/<pid>.json` 的 `"status"` 为 `"idle"` / `"shell"` 或存在 `"parkedJobId"` 时返回 `status: Some(Status::Idle)`。
- `crates/uniflo-core/src/status.rs` & `crates/uniflo-core/src/engine.rs` & `docs/architecture.md`：
  - `effective()` 在 `live_status` 与 `tracker.status` 一致时保留原 `reason`（如 `"turn_end"`）；在 `live_pid == true` 且 `live_status == None` 时禁用 90s `settle`，并将静默超时窗口设为 `3 * stale_ms`（默认 30 分钟），防止异常中断未关终端的会话永久卡在 `work`。
  - 升级索引缓存 tag（`schema1-r2`），自动刷新旧缓存中的会话状态与预览。

## 3. 网页端「用量与费用」自定义日期弹窗无法关闭修复

### 现象与根因

- 点击「自定义」按钮打开 Air Datepicker 日历弹窗后弹窗一直不消失：
  1. 点击「自定义」时通过 `setTimeout(() => datePicker.show(), 0)` 打开弹窗，未聚焦 `#u-dates` 输入框，导致 Air Datepicker 唯一依赖的 `#u-dates` `blur` 事件永远无法触发，点击页面外部、切换其他时间范围或切换顶部视图都不会关闭弹窗；
  2. 预填 `[from, to]` 两个日期后，因 `toggleSelected: false`，点击已选中的端点日期（如当天 `12`）命中 `_handleAlreadySelectedDates` 的空分支，无法重新以当天作为起止点；
  3. `.air-datepicker` 默认 0.3s CSS 过渡依赖异步 `transitionend` 才移除 DOM。

### 改动

- `examples/web/index.html` & `crates/uniflo-gateway/src/index.html` & `scripts/demo-e2e.mjs`：
  - 为 `.air-datepicker` 设置 `--adp-transition-duration: 0s; transition: none`；
  - 新增 `closeDatePicker()`：在点击弹窗与输入框外部、切换非 `custom` 时间段、再次点击 `custom`、切换顶部视图或按下 `Escape` 时立即关闭弹窗；
  - 配置 `toggleSelected` 在已选满 2 个日期时允许点击任意已选端点重新开始选区，选满 2 个日期后自动关闭弹窗；
  - 在 `scripts/demo-e2e.mjs` 增加点击外部关闭与点击输入框重开的端到端断言。
