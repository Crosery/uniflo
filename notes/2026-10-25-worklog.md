## 2. 未定价模型的匹配

- 起因：用户截图「未定价的模型」，认为这些模型在 models.dev / OpenRouter 都有，只是没按相似度匹配。
- 核对（下载 models.dev `api.json`：230 家、8,894 个模型；OpenRouter `/api/v1/models`：469 个；只看计数与 id）：
  - 本机 `/v1/models`：116 个模型名，其中 58 个有未定价步，共 74,064 步。
  - 50 个在上游能找到对应条目（占未定价步数 99.5%）。
  - 原因有两个：
    - 只读 10 家官方厂商，缺 xiaomi、meta、stepfun 等官方 provider；deepseek-v4.1-flash、hy4 等只挂在转售方名下（deepseek-v4.1-flash 有 72 家）。
    - harness 给名字加了前缀或后缀（`qcn-`、`cline-`、`-high`、`-free`、`:free`、`-expires-on-0910`）。
  - OpenRouter 的顶层报价是它最便宜的线路，不能直接当价格：glm-5.3 输入 0.079，官方 1.4；kimi-k3 0.239，官方 3；deepseek-v4.1-flash 0.02，72 家的中位数 0.236。
- 做法（Sonnet 子 agent 在独立 worktree 实现，主模型审查并改了一处）：
  - 官方厂商加 6 家：xiaomi、meta、stepfun、mistral、cohere、perplexity。
  - 官方都没有的模型名，取其余 provider 的中位价。OpenRouter 只是其中一票；免费版和 0 价不参与。
  - 名字窗口：按 `-`、`:` 切词，从长到短试去掉前缀或后缀的子名字，命中标 `approx`。去掉的末尾词不能是档位词（mini、flash、max…），防止 `gpt-5-mini` 按 `gpt-5` 计价。
  - 主模型改的一处：两个词以上的窗口不再要求带数字，`oc-space-bunny` 能配上 `space-bunny`，`mimo-auto` 仍然不会缩成 `mimo`。
- 真实数据验收：
  - 环境：只读副本守护进程，`HOME`、`UNIFLO_DATA_DIR`、`UNIFLO_CACHE_DIR` 用临时目录；价格源 `UNIFLO_PRICING_URL` 指本地 HTTP 服务上的同一份 `api.json`，`UNIFLO_PRICING_FALLBACK_URL=` 置空；`--no-fts --read-only`，端口 7462。真实价格目录未动。
  - 结果：未定价从 58 个模型、74,064 步降到 12 个、492 步（−99.3%）。
  - 剩下的 12 个，上游要么没有，要么只有 0 元的免费版或路由：`qfmodel`、`dfmodel`、`gfmodel`、`mimo-auto`、本地模型路径、`stealth/ox-alpha`、`notion/opus-5.5`、`claude-4.6-opus-max-thinking`（词序不同且带档位词）、`x-preview-f-free`、`apodex-1.1-mini:free`、`dots-3-note-preview:free`、`openrouter/free`。
  - 免费版（`-free`、`:free`）按对应付费模型的价格近似，与 ADR-0010 的「API 等价成本」口径一致。
- 内置快照 `pricing-snapshot.json` 没有重新生成（需要联网），新厂商与转售中位价都来自守护进程的在线同步。

## 10. Windows 上旧全文索引删不掉

- 推送 `a1606aa` 后 Windows CI 换成 `uniflo-search` 的 3 个迁移测试失败（`migrate.rs` 的 `!old_path.exists()` 断言）。
- 原因：`fts::migrate::migrate` 删除 `fts-v1.sqlite` 时，旧库的 SQLite 连接还开着。macOS / Linux 允许删除打开中的文件，Windows 不允许，`remove_file` 的错误又被忽略。影响已发布的 0.2.0：Windows 用户升级后旧索引一直留在磁盘上、空间不回收，`reclaimed_bytes` 却报成旧文件大小，`fts.migrating` 也一直为真，每次启动都重新打开旧文件。
- 修复：每次删除前先关闭旧连接；`remove_old` 返回主文件是否已删除，没删掉时 `reclaimed_bytes` 记 0。本机 `cargo test -p uniflo-search` 65 个通过，1.94 与 1.99 的 clippy 都无告警；Windows 上的验证看推送后的 CI。
- 门禁：`scripts/verify.sh` 的 `cargo test` 加 `--no-fail-fast`。之前 Windows CI 每轮只暴露第一个失败的测试二进制（这次是第二轮才看到迁移测试）。

## 11. 子代理默认只显示工作中的

- 起因：用户看了真实数据上的树形列表，要求默认只显示正在工作的子代理：没有工作的子代理时不展开，有工作的才展开且只列工作中的，其余通过「加载更多」查看。

## 12. 0.2.1：升级体验、提示语言、控制台随升级刷新

- 起因：用户在另一台机器上 `uniflo update`（0.2.0-beta.3 → 0.2.0），输出有整段 cargo 编译日志、错误的重启提示（`uniflo daemon`，实际要 `--restart`）、从头走一遍 `uniflo setup` 的提问；后台守护进程（`uniflo daemon` 起的，pid 60786）没重启，`/demo` 页面也还是旧的。要求：交互改好看；中文系统中文、其他英文；控制台随升级同步；做完发 0.2.1。
- 语言：新增 `uniflo-cli::i18n`（`tr!` 宏），依次看 `UNIFLO_LANG`、`LC_ALL`、`LC_MESSAGES`、桌面语言（macOS `AppleLanguages`、Windows `GetUserDefaultUILanguage`）、`LANG`。桌面语言排在 `LANG` 前面，因为终端常把 `LANG` 设成 `en_US.UTF-8`。CLI 的提示、报错（含顶层 `uniflo: 错误：`）、`install.sh` / `install.ps1`（`.ps1` 仍是纯 ASCII + `\uXXXX`）都改成双语；JSON、TSV、MCP、`uniflo context` 不翻译。集成测试固定 `UNIFLO_LANG`，单元测试默认中文。
