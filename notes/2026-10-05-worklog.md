## 做了什么

1. **分支生命周期与版本号规划**：
   - 遵循 `geek_main` 规范，从最新 `stage` 检出短生命周期任务分支：`task/windows_support`。
   - 统一提升版本号至 `0.1.2`（全 workspace 联动）。

2. **Windows 平台进程存活与探针特化 (`uniflo-core`)**：
   - `pid_alive(pid: u32)`：Unix 保持 `libc::kill(pid, 0)`；Windows 特化使用 Win32 `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` 与 `GetExitCodeProcess`（状态码 259 `STILL_ACTIVE`）。
   - `procs::list`：Windows 特化使用 PowerShell `Get-CimInstance Win32_Process` 获取系统进程号与完整命令行，在 Windows 上实现进程匹配。

3. **跨平台时钟格式化去 libc (`uniflo-cli`)**：
   - 将 `render.rs` 中的 `libc::localtime_r` 替换为已引入的 `chrono::DateTime<chrono::Local>`，完全去除 unsafe 块与 libc 绑定，在 Windows、Linux、macOS 全平台一致。

4. **Harness 存储路径 Windows 映射 (`uniflo-adapters`)**：
   - `cline.rs`：新增 `#[cfg(target_os = "windows")]`，映射至 `%APPDATA%\<app>\User\globalStorage\<ext>\tasks`。
   - `opencode.rs`：新增 `data_home()`，在 Windows 下优先读取 `%LOCALAPPDATA%`，自动匹配 `%LOCALAPPDATA%\kilo\kilo.db` 及 `opencode.db`。

5. **文件系统变更通知自适应 (`Cargo.toml`)**：
   - 移除 `notify` 硬编码的 `macos_fsevent` 特性，使 Windows（ReadDirectoryChangesW）、macOS（fsevent）、Linux（inotify）自动采用各自原生高效后端。

6. **三平台真实运行烟测与 CI 流水线 (`scripts/daemon-smoke.mjs` & `ci.yml`)**：
   - 新增 `scripts/daemon-smoke.mjs`：真实启动 `uniflo daemon`，监听端口并请求 `/v1/health`、`/v1/harnesses`、`/demo` 与 `/v1/sessions`，断言返回状态码与数据。
   - 将 `windows-latest`（微软官方真实 Windows Server 环境）加入 GitHub Actions 自动化矩阵：`os: [ubuntu-latest, macos-latest, windows-latest]`。
