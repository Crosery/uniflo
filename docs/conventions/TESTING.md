# 测试与验收规范

> 先写可观察的完成条件，再实现；证据分层，不互相替代。

状态：`current` · 更新：2026-10-02

## 完成条件

- 行为改动动手前写下可观察的完成条件（输入 → 预期输出/状态）。
- 缺陷修复要有「修前失败、修后通过」的证据；自动化成本过高时记录可复现的手工证据和原因。

## 按风险选检查

| 级别 | 范围 | 最少证据 |
|---|---|---|
| R0 | 纯文档、注释、格式 | 链接与格式检查 |
| R1 | 单模块逻辑 | 覆盖改动分支的单测 |
| R2 | 跨模块、公共 API、依赖、UI 流程、构建配置 | 集成/契约测试 + 实际走一遍改动路径 |
| R3 | 数据迁移、身份授权、生产基础设施、不可逆副作用 | R2 + 回滚方案 + 用户确认 |

## 证据分层

类型检查、单测、构建、mock 预览、浏览器实测、线上验收是不同层次的证据。报告里逐项写：命令、真实结果、没跑的项与原因。没验证写「未验证」。

## 统一入口

`scripts/verify.sh` 是交付前的统一验收入口；新增检查挂到它下面，不另起一套。
