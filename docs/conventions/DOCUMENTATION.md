# 文档规范

> 当前事实、已接受决策、未实施提议、历史材料分开写；一种知识只有一个真源。

状态：`current` · 更新：2026-10-02

## 放哪

| 内容 | 位置 |
|---|---|
| agent 行为规则与指针 | 根 `AGENTS.md`（唯一 agent 入口，只放规则与指针） |
| 人读总览、快速开始 | 根 `README.md` |
| 规范、架构、契约 | `docs/`，入口 `docs/README.md` |
| 长期决策 | `docs/decisions/ADR-NNNN-中文标题.md` |
| 每天的过程记录 | `notes/YYYY-MM-DD-worklog.md` |
| 证据（日志、截图、生成物元数据） | `notes/evidence/` |
| comet 流程产物 | `docs/comet/`（工具维护，不手改） |

## 怎么写

- 每篇：一级标题 → 引用块一句话摘要 → `状态：<词> · 更新：YYYY-MM-DD` → 正文。
- 状态只用四个词：`current` 当前有效、`accepted` 已接受决策、`proposed` 未实施提议、`historical` 历史记录。`accepted` 不等于已落地，正文写实施状态。
- 事实给来源：本地事实给文件路径或命令，外部事实给官方链接与核对日期。未落地的目标只写在 `proposed` 里。
- 能从 manifest、配置、`--help` 一眼查到的不抄进文档；只写查不到的约定、原因和坑。
- 链接用相对路径；移动文件后核对所有相对链接。

## 同步

改接口、环境变量、端口、命令、目录边界时，同一提交里改对应文档。发现 `current` 文档与代码不一致：先改文档，再继续。

## worklog

每次会话追加 `notes/YYYY-MM-DD-worklog.md`：时间、动作、依据、结论；失败与教训直接写，验证命令和真实结果写进去。

## ADR

复制 `docs/decisions/ADR-0000-模板.md`，编号递增：状态、背景、决策、否决项、后果、复议触发。
