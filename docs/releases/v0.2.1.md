## Uniflo 0.2.1

0.2.0 之后的修复版：升级体验、按系统语言显示提示、控制台随守护进程升级自动刷新、子代理默认只显示工作中的，以及 Windows 上旧全文索引删不掉的问题。

### 安装与升级

- `cargo install uniflo`
- 已装 0.2.0 或更早：`uniflo update`
- 预编译包：一行安装脚本（`install.sh` / `install.ps1`，见 README），或 `cargo binstall uniflo`

从 0.2.0 升级时，安装这一步仍由 0.2.0 执行，所以 cargo 的编译日志还会照常打印；之后的收尾（重启守护进程、刷新接入）由 0.2.1 完成。0.2.0 时打开的 `/demo` 页面需要手动刷新一次，此后会自动刷新。

### 变化

| 模块 | 内容 |
|---|---|
| `uniflo update` | 每步一行：`uniflo 0.2.1 → 0.2.2`、编译进度（cargo 日志收成一行，失败时才打印最后 40 行）、已安装、守护进程、接入。装好后由新版本收尾：`uniflo daemon` 起的后台守护进程若还是旧版本，按原来的参数重启（参数记在缓存目录的 `daemon.json`，不含 token）；macOS launchd 服务运行的就是这个可执行文件时 kickstart；接入过 agent 时静默刷新并打印一行汇总，不再重走整套提问 |
| 提示语言 | CLI 与安装脚本的提示、报错按系统语言显示：中文系统中文，其他英文。依次看 `UNIFLO_LANG`、`LC_ALL`、`LC_MESSAGES`、桌面语言（macOS 首选语言、Windows 显示语言）、`LANG`；JSON、TSV、MCP 输出不翻译 |
| `uniflo setup` | 提问与计划改成分组排版，结果行用 ✓ / · / ! / ✗ 标记，已就绪的条目不再重复「未变化」 |
| 网页控制台 | 守护进程换了版本（`/v1/health` 或重连时的 `hello`）就自动刷新一次，视图、查询与选中会话保留；子代理默认只列工作中的，空闲的按需加载（每次 10 个），一家没有在工作的子代理时收成一行 |
| Windows | 旧版全文索引 `fts-v1.sqlite` 转换完成后先关闭连接再删除；0.2.0 在 Windows 上会留下旧文件，并误报已回收的空间 |
| 测试 | `scripts/verify.sh` 的 `cargo test` 加 `--no-fail-fast`，一次列出所有失败的测试二进制；时区非法值用例改成各平台都非法的写法 |
