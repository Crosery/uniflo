## Uniflo 0.2.6

更新检查与升级在中国大陆不再卡住：版本检查同时有官方源和国内镜像，下载在 GitHub 连不上时自动改经加速站。

### 安装与升级

- `cargo install uniflo`，或已安装时运行 `uniflo update`。
- 0.2.5 及更早的版本在中国大陆检查更新失败时，可以先用一次：
  `UNIFLO_UPDATE_INDEX_URL=https://rsproxy.cn/index/un/if/uniflo UNIFLO_RELEASE_BASE_URL=https://ghfast.top/https://github.com/Crosery/uniflo/releases uniflo update`
- 预编译包覆盖 macOS arm64 / x86_64、Linux x86_64 / aarch64（musl）、Windows x86_64，附 `SHA256SUMS`。
- 升级后首次启动会重建一次会话索引与用量缓存（缓存标签变化），全文索引不重建。

### 变化

| 模块 | 变化 |
|---|---|
| 地区判断 | 只看本机时区：中国大陆时区先用国内镜像，其他地区先用官方源；`UNIFLO_MIRROR=cn` 或 `official` 可以指定 |
| 版本检查 | 官方 `index.crates.io` 与 rsproxy.cn、中科大镜像两组源；首选组 2 秒内没有回答或失败就同时问另一组，取各源中最新的版本，同步滞后的镜像不会把新版本藏掉 |
| cargo 升级 | 中国大陆时区、且 cargo 配置没有自己替换源时，`cargo install` 经 rsproxy.cn 下载依赖 |
| 发布包下载 | `uniflo update` 和安装脚本先连 GitHub，连接超过 8 秒或速度过低时依次改经 ghfast.top、gh-proxy.com；`SHA256SUMS` 按同样顺序获取 |
| 提示 | 检查失败时列出每个源的失败原因，并提示可用 `UNIFLO_MIRROR` 指定源 |

本机实测（中国大陆网络，无代理）：版本检查按中国大陆时区 1.05 s、按海外时区 1.56 s；GitHub 直连下载发布包连接超时，经 ghfast.top 6.7 s 下完 6 MB，校验值一致。

没有新增生产依赖。
