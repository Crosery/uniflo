## Uniflo 0.2.5

0.2.4 的修复版：全文索引空闲时不再持续占用 CPU，冷查询更快，建库后新增的会话会如实显示建库进度；MCP 从本地索引切回守护进程后归还内存。

### 安装与升级

- `cargo install uniflo`，或已安装时运行 `uniflo update`。
- 预编译包覆盖 macOS arm64 / x86_64、Linux x86_64 / aarch64（musl）、Windows x86_64，附 `SHA256SUMS`。
- 安装脚本与 `cargo binstall uniflo` 使用同一批发布包，见 README。
- 升级后首次启动会重建一次会话索引与用量缓存（缓存标签变化），全文索引不重建。
- 升级后重新连接旧的 MCP 进程，使其加载新版。

### 变化

| 模块 | 变化 |
|---|---|
| 全文索引 | 空闲时不再每 100 ms 克隆全部会话找降温候选，降温与空间回收检查改为每秒一次，会话没有变化时对账跳过 |
| 建库进度 | 建库完成后新出现的会话立即计入进度，`indexing` 短暂为 true、建好后回到 false，`progress.done` 不回退 |
| 全文检索 | 冷层块由各校验线程并行读取，字符折叠改查稠密表，每次查询只算一次热层 IDF；首次（冷）查询仍返回完整结果 |
| MCP | 守护进程恢复后，`uniflo mcp` 丢掉进程内索引并把内存交还系统 |

隔离环境实测，与 0.2.4 对比：
- 3001 个合成会话、建库完成且没有写入：守护进程空闲 CPU 3.0% → 0.18%。
- 本机真实索引（5240 个会话）、冷缓存，20 个词各查 5 次、4 轮取中位数：首次查询 p95 1847 → 940 ms，最慢 3958 → 2799 ms；全部查询 p50 约 10 → 5.5 ms。
- MCP 退回本地索引回答后再连上守护进程：298 MB → 约 10 MB。

没有新增生产依赖。
