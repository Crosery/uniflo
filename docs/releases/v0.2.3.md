## Uniflo 0.2.3

可靠性修复版：解决全文索引 `database is locked` 后持续报错和漏内容，按本轮进入工作状态的先后固定会话与子代理队列，并修复 Windows、Linux、macOS 的平台缺陷。

### 安装与升级

- `cargo install uniflo`，或已安装时运行 `uniflo update`。
- 预编译包覆盖 macOS arm64 / x86_64、Linux x86_64 / aarch64（musl）、Windows x86_64，附 `SHA256SUMS`。
- 安装脚本与 `cargo binstall uniflo` 使用同一批发布包，见 README。
- 升级后重新连接旧 MCP 进程，使其加载新版；不需要删除全文索引或会话数据。

### 修复

| 模块 | 变化 |
|---|---|
| 全文索引 | 同一索引的跨进程写租约保证单写者；其他进程只读已提交 WAL，并在写者退出后接管，不再互相争写 |
| 全文索引 | 使用立即写事务，避免旧读快照无法升级；显式索引和删除请求直到提交成功才完成，回滚不会丢失已接收内容 |
| 缓存安全 | 读取索引标签遇到锁、权限或 I/O 错误时保留原索引，不再误判损坏并删除重建 |
| MCP | 守护进程恢复后自动离开本地回退、释放本地索引并重新使用守护进程，不再长期停留在旧快照 |
| 网页控制台 | 工作中按本轮进入 work 的先后固定排列；回复、工具输出和用量更新不改位置；空闲后再次工作排到队列末尾；子代理和持续工作的父家族遵守同一规则 |
| Linux | 进程参数保留 `/proc/<pid>/cmdline` 的 NUL 边界，`--resume` 路径含空格时仍可精准关联会话 |
| macOS | 同一物理目录有 symlink、canonical 或重叠配置根时，文件变化通知映射到全部匹配根，不再漏实时更新 |
| Windows | 连续升级时避开仍被进程占用的旧备份文件；失败回滚使用本次备份，不误删名称相近的其他文件 |

会话与用量数据格式不变，没有新增生产依赖，也不要求重建全文索引。
