# ADR-0001 · Rust 单守护进程 + 本地网关

> 用一个 Rust 守护进程统一索引所有 harness，对外只暴露本地 HTTP 网关；应用不直接读 harness 文件。

状态：`accepted` · 更新：2026-10-09

## 背景

本机同时跑着 Claude Code、Codex、omp 等 20 个 harness，会话总量数千、原始数据约 1.8 GB，且在持续追加。要求：所有请求毫秒级、流式输出实时反映、多个桌面端/网页端同时接入。

## 决策

- 一个常驻进程 `uniflo daemon`（Rust，tokio + axum）持有全部索引；客户端通过 `127.0.0.1:7311` 的 REST / SSE / NDJSON / WebSocket 接入。
- 代码按 crate 拆分：`schema`（契约）→ `core`（引擎）→ `search` / `adapters` → `gateway` → `cli`；每个 harness 是 `adapters` 内一个 feature。
- CLI 既能连守护进程，也能 `--local` 进程内索引（无守护进程时可用）。

实施状态：已落地（`crates/*`）。

## 否决项

- 每个应用自己读 harness 文件：格式适配重复 N 次，且多个进程各自全量解析，冷启动秒级。
- Node/Python 实现：冷启动全量解析 1.8 GB 的耗时与常驻内存不满足毫秒级目标。
- 嵌入式数据库（SQLite 索引）：要维护第二份数据和迁移；头尾摘要 + 游标 + JSON 缓存已足够快（有缓存启动约 200 ms）。
  - 2026-10-09 修订：事件正文的全文检索改用缓存目录里的 SQLite FTS5 索引，见 `ADR-0008-全文检索索引.md`。会话表、游标和启动缓存仍按本条，不迁入 SQLite。

## 后果

- 收益：一份解析、多端共享；网关读快照不经过写循环，读延迟稳定。
- 代价：守护进程是单点；需要处理缓存失效（标签含版本、schema、适配器列表）。

## 复议触发

需要跨机器聚合、或会话量增长到内存快照不可接受（> 10 万会话）时。
