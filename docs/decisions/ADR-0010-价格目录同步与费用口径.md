# ADR-0010 · 价格目录同步与费用口径

> 每一步按「harness 自报金额 → 事件时间所在价格段 → 不定价」算费用；价格来自内置快照、守护进程用系统 `curl` 同步的上游目录和用户覆盖文件，同步只追加价格段、带安全阀。

状态：`accepted` · 更新：2026-10-25

## 背景

用户要按 harness、模型、项目、时间看 token 和花费。约束：

- 各 harness 记录用量的口径不同（input 是否含缓存、output 是否含思考），只有少数自报金额。
- 订阅用户没有按量账单，金额只能是"API 等价成本"。
- 价格会变；历史用量不能因为今天调价而改变，重启重建索引后结果也必须一样。
- 依赖树里没有 HTTP/TLS 客户端，新增生产依赖需要批准（同 ADR-0005）；守护进程默认只读、只听本机。

## 决策

- **usage 口径**（wire schema 只增，见 `docs/schema.md#usage-口径`）：`input` 不含缓存、`output` 含思考、`reasoning ⊂ output`；新增可选 `model`、`cost_usd`。各适配器在读入时换算（`docs/adapters.md#usage-口径`），引擎为缺模型的步骤补会话最近的模型。
- **费用顺序**（`crates/uniflo-core/src/usage/mod.rs` `Step::price`）：
  1. 有自报 `cost_usd > 0` → 直接采用，`cost_source=harness`；
  2. 否则在价格目录里找模型，按**事件时间**所在价格段计算，`cost_source=catalog`（精确匹配）或 `approx`（近似）；
  3. 都没有 → `cost_usd=null`，计入 `unpriced_steps`，从不按 0 计。唯一的例外：一步的 token 全为 0（`qoder` 的 `qfmodel`、`pi` 的 `free` 这类空记录）没有可计价的东西，费用按 0、`cost_source` 为空，不算未定价。
- **公式**（`pricing/catalog.rs` `step_cost`）：`(input×in + output×out + cache_read×cr + cache_write×cw) / 1e6`；缺 `cw` 按 `in × 1.25`；缺 `cr` 按 `in`；分档按整单 prompt（`input + cache_read + cache_write`）严格大于 `above` 时整单换档价。
- **价格三层**：`<数据目录>/pricing/overrides.json`（用户手写，任何同步都不改）> `catalog.json`（同步结果）> 内置快照 `crates/uniflo-core/data/pricing-snapshot.json`（`scripts/build-pricing.mjs` 生成：models.dev 为主，LiteLLM 补缺）。同名（归一后）以高层为准。
  - 官方厂商 `FIRST_PARTY`（`anthropic`、`openai`、`google`、`minimax`、`moonshotai`、`zai`、`deepseek`、`alibaba`、`xai`、`groq`、`xiaomi`、`meta`、`stepfun`、`mistral`、`cohere`、`perplexity`）的自报价直接采用。
  - 其余所有 models.dev provider（转售方、聚合器，含 OpenRouter 自己）按模型名分组，取 input/output/cache_read 的中位数做成一条"转售中位价"条目（`catalog.rs` `parse_resellers`）：排除 id 以 `:free`/`-free` 结尾或价格为 0 的条目，它们不进中位数；只有官方厂商都没有列出的名字才会落到这一层，官方价永远优先。例外：id 以 `:free`/`-free` 结尾、input 与 output 都明确标 0、且全网没有任何一家列出去掉后缀的付费同名模型（`x-preview-f-free`、`dots-3-note-preview:free`），按零价单独成一条——这是挂牌的免费档，不是缺价；有付费同名模型时照旧按付费模型计价（API 等价成本）。不直接用 OpenRouter 等单一转售方的报价——转售方的挂牌价常常是它自己最便宜的路由而不是厂商价（如 glm-5.3 input OpenRouter 报 $0.079/M，智谱官方 $1.4/M；kimi-k3 OpenRouter 报 $0.239/M，官方 $3/M），单一转售价不可信，中位数才接近真实成本。
- **模型名归一**（`catalog.rs` `match_key` / `Catalog::resolve`）：
  1. 去 `provider/` 前缀、`[...]` 后缀、末尾 `(…)` 修饰 → 小写、`4.5`≡`4-5` → 去日期后缀（`-20250929`、`@20250929`、`-2025-09-29`；带日期的目录 id 也能回答不带日期的名字，取最新）精确匹配整名。
  2. **厂商显示名**（借鉴 crosery-api-console `sync.mjs` 的 `normalizePricingName`）：官方厂商自己的条目带 `name`（`CatalogEntry.name`，如 models.dev 里 deepseek 把 V4.1 Flash 登记为 id `deepseek-flash`、显示名 `DeepSeek V4.1 Flash 1017`）。显示名与模型名各自只留 ASCII 字母数字、转小写、去掉末尾 4–8 位数字（构建号或日期，`display_key`），相等即命中，标 `approx`。多家厂商同名时，provider 是名字前缀的那家（`deepseek…`）胜出，否则要求价格一致，否则不猜。厂商条目（按 id 或按显示名）优先于转售中位价——转售中位价条目带 `consensus: true`，只有厂商没有这个名字时才用它。用户 `overrides.json` 与同 id 的非中位条目不受显示名回退影响。
  2b. **改写拼法**（`respellings`，与整名一起先试，厂商条目优先于转售中位价）：Cursor 等编辑器把版本写在家族名前面（`claude-4.5-opus-high-thinking` → `claude-opus-4-5-high-thinking`），或省掉厂商前缀（`opus-5.5` → `claude-opus-5-5`）。只有这两种固定写法会被改写。
  3. 仍找不到时，按 `-`/`:` 切词，试去掉前缀或后缀的"名字窗口"（`name_windows`）：从最长的窗口开始，同长度优先去掉前导词（命中 harness/转售方自己加的前缀，如 `qcn-`、`cline-`）；窗口必须以 ASCII 字母开头、含 ASCII 数字或至少两个词（`oc-space-bunny` → `space-bunny`；`mimo-auto` 不会缩成单词 `mimo`），且被去掉的**末尾**词不能是档位词（`mini/nano/.../flash/pro/max/plus/.../base` 等，见 `TIER_WORDS`）——防止 `qwen3.8-max` 误配成 `qwen3.8`、`gpt-5-mini` 误配成 `gpt-5`。窗口命中（含去日期）同样标 `approx`；每个窗口同样先按厂商 id、再按厂商显示名、最后按中位价查找。
  4. **相似度匹配**（`Catalog::similar`）：名字比目录里的某个 id 多出前缀、后缀、档位或词序不同（`cursor-claude-4.5-opus-high-thinking`、`gpt-5-high-fast` ↔ `gpt-5-fast`）时，按词比较（`-`、`:`、`.`、字母/数字交界处都切开，去掉发布日期）。目录 id 命中需同时满足：id 的所有词都在名字里；版本号数字串（`4 5`、`70`）与名字完全相等，因此 `gpt-5` 不会顶替 `gpt-5.1`、`llama-3.1-70b` 不会丢掉尺寸；名字里的档位词（`TIER_WORDS`）id 里也要有，Claude 名字上的 `max`/`medium` 只表示思考强度，除外；id 至少两个词，且占名字词数的一半以上。多个候选取词数最多的，同样多时厂商条目优先于转售中位价。窗口命中的是转售中位价时，厂商条目的相似度命中优先于它。标 `approx`。
  5. 仍找不到时取同骨架（数字换成 `#`）版本号最近的条目，先试整名、再试每个窗口，标 `approx`。相似度匹配排在它前面：版本完全一致的命中比"最近版本"更可信。
- **同步**（`pricing/sync.rs`）：守护进程启动约 60 s 后一次、之后每 6 h 一次（`PriceSync`），`uniflo pricing sync` 随时手动；用系统 `curl -fsS --max-time 20` 拉 `UNIFLO_PRICING_URL`（默认 models.dev `api.json`）和 `UNIFLO_PRICING_FALLBACK_URL`（默认 LiteLLM，设为空串关闭）。`--no-price-sync` 完全不联网。
  - 已有条目价格不变时，也会刷新 `name` 与 `consensus`（旧版 `catalog.json` 没有这两个字段）。
  - 价格与上次不同 → 当前段在**观测时刻**截止（`until`），新段从观测时刻开始；此前的步骤仍按旧段计价。
  - 任一分项变化超过 50% → 记为待确认，连续两次读到同样的新价才生效；缺失值或 0 不视为降价（沿用旧值）。
  - 主源失败时，主源拥有的条目保留，不被备源接管；全部失败或返回空 → 不改 `catalog.json`，`error` 记原因。
  - 写入一律临时文件 + `fsync` + `rename`；同步状态（待确认、各源结果、最近尝试）在 `sync-state.json`。
  - 超过 24 h 没有成功同步（只有内置快照也算）→ `stale=true`。
- **生效**：守护进程每秒检查三份文件的大小与 mtime，变化即重载并对全部步骤重新计价；`uniflo pricing sync` 在 CLI 进程里执行，不需要网关写接口。

## 否决项

- 只用 harness 自报金额：多数 harness 不报（Claude Code、Codex、Gemini 都没有），统计会大面积为空。
- 价格覆盖整段历史（不分段）：调价后历史费用跟着变，重建索引结果不可复现。
- 未知模型按 0 计：总额被系统性低估且看不出来；改为单独计数 `unpriced_steps`。
- 加 HTTP 客户端依赖（`ureq` + `rustls`）：同 ADR-0005，一个 GET 不值得引入新生产依赖。
- 网关提供 `POST /v1/pricing/sync`：网关保持只读（ADR-0004 的攻击面），手动同步走本机 CLI。

## 后果

- 守护进程多一类出站请求（价格目录，无会话数据，UA 只有版本号）；README 与 `docs/api.md` 写明 `--no-price-sync`。
- 内置快照随版本发布更新：改价格来源或过滤规则后重跑 `node scripts/build-pricing.mjs` 并提交生成物（快照带厂商显示名；快照越旧，全新安装在首次同步前越多模型未定价，发版前要重新生成）。
- 金额是 API 等价成本，订阅用户的真实账单不同；所有界面都这样标注。
- 近似匹配可能偏差（如新版本按旧版本计价、`gpt-5-high-fast` 按 `gpt-5-fast` 计价），以 `approx` 明示；用户可用 `overrides.json` 纠正。
- 仍然定不了价的是：名字没有任何公开价格的（Cursor 的 `composer-*`、小米 MiMo Code 的 `mimo-auto`、各种内部代号），以及 harness 根本没记录模型的步骤（Cursor 旧版会话的多数气泡在库里任何位置都没有模型名，见 `docs/adapters.md#usage-口径`）。这两类靠更多价格来源解决不了。
- `catalog.json` 与快照都会增长价格段；条目数在千级，内存与解析成本可忽略。

## 复议触发

- 上游目录格式变化或长期不可用，需要换源或改为随版本发布的离线价格。
- 需要按真实账单（含折扣、批量价、地域价）对账时，费用模型要扩展。
- 出现 harness 自报金额与目录计价系统性不一致的情况时，重新评估来源优先级。
